# 炁渊 · QI ABYSS

新中式绮丽 · 回合制卡牌对战手游（手机竖屏 390×844）

> 以中国「五正色 + 干支历法」为骨、以「性命双修」为魂的卡牌对战。
> 阳炁阴炁双资源、弹反微操、五行连携、二十四节气变量联动。

---

## 一、这是什么

《炁渊》是一款运行在手机浏览器竖屏（基准 **390 × 844**）的单机回合制卡牌对战游戏。
无后端、无账号、无网络依赖，全部战局在浏览器内完成，进度存 `localStorage`。

**它解决什么问题**：传统回合制卡牌的战斗是「选牌 → 看数字跳」。本项目尝试把**动作游戏的即时操作**塞进回合制框架 ——
敌方出招前有前摇条，玩家要在判定窗内按下格挡键：红区是普通格挡（减伤），金区是完美弹反（免伤 + 追击）。
再叠加双资源（阳炁/阴炁）的收支博弈、五行相生链的连携顺序、以及二十四节气对全局数值的乘区扰动，
让每一回合都有「资源算账 + 手速判断 + 组合规划」三层决策。

**技术上的核心命题**：战斗引擎是**纯函数 + 确定性**的 —— 相同随机种子必然复现完全相同的战局。
这条约束不是洁癖，而是让 100+ 条单元测试可以对战局做逐帧断言，也让 UI 的动画层可以随时脱离引擎重放。

## 二、快速开始

### 环境要求
- Node.js **18+**（开发使用 22.x）
- 包管理器：npm（仓库内提交了 `package-lock.json`，可复现安装）

### 安装与运行

```bash
npm ci             # 按锁文件安装依赖（推荐，可复现）
# 或 npm install

npm run dev        # 启动开发服务器
# 浏览器打开后按 F12 → 切换设备工具栏 → 选 iPhone 12/13 (390×844)
```

### 构建与预览

```bash
npm run build      # 架构守卫 → 类型检查 → 生产构建，产物在 dist/
npm run preview    # 预览构建产物
```

> 若在受限环境（如沙箱）中 `npm run build` 报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，
> 是宿主对 `dist/art` 批量删除的保护，改用 `npm run build:safe`（跳过清空目录）。

### 测试与静态检查

```bash
npm run test       # vitest run，102 条单元测试
npm run lint       # oxlint
npm run guard      # 架构守卫（8 项检查：引擎随机源 / hex 越界 / 节气铁律 / 死代码等）
npx tsc -b         # 类型检查
```

### 运行产物

`dist/` 是一份**纯静态站点**（HTML + 一个 JS bundle + CSS + `public/art` 素材），
可直接由任意静态服务器托管，或用 `npm run preview` 本地预览。
打开后首先进入主界面，点「入局」→ 择道面板（三选一角色）→ 战斗 → 结算。

## 三、技术栈与工程约束

**Vite 8 + React 19 + TypeScript 6 + oxlint + vitest**

依赖只有 `react` / `react-dom` 两个运行时包。
**零第三方 UI 库、零状态管理库**（MUI / Tailwind / Framer Motion / zustand 均被刻意否决），
所有界面手写 CSS + 项目自有组件。

| 约束 | 内容 |
|---|---|
| 颜色唯一真源 | `src/styles/tokens.css` 是全项目**唯一**允许出现 hex 字面量的文件，其余一律 `var(--color-*)` 或 `rgba()` |
| 引擎确定性 | `src/game/engine/**` 禁 `Math.random` / `Date.now`，随机走 `state.rngState`（mulberry32） |
| 节气零改引擎 | `engine/hooks.ts` 是唯一读 `solarTermId` 的地方，新增节气只加数据 |
| 禁止无响应系统 | 任何声明的状态/机制必须在引擎里有真实效果，且敌我双向结算 |
| 素材必降级 | 用素材处必须「基底 CSS 层 + 透明叠加层 + 内容层」三层兄弟节点，缺图不白屏 |
| 类型级守卫 | 新增状态 / 效果 / 装备字段不登记即**编译失败**；契约测试 33 条覆盖数据完备性 |

上述约束由 `npm run guard` 与 `tsc` 强制执行，详见 [`AGENTS.md`](AGENTS.md)。

## 四、核心系统

| 系统 | 说明 |
|---|---|
| **双脉炁资源** | 阳炁（攻击/击杀获得）+ 阴炁（受击/格挡获得），可 2:1 互转；每回合自动回炁 +3/+3 |
| **弹反微操** | 敌方前摇后进入判定窗，红区=普通格挡（减伤），金区=完美弹反（免伤 + 追击） |
| **奥义卡** | 两张同属性牌合并，融合后按五行/物理/功能分七种专属演出 |
| **破绽** | 回合结束按连击/相克给敌人标记，下回合首张攻击牌必暴击且转真实伤害 |
| **三大架势** | 体修（叠「势」层数）/ 法修（五行相生链）/ 散修（阴阳差值转化暴击） |
| **装备附魔** | 3 兵刃 + 3 法器，9 种组合产出不同斩击，双兵刃/双法器/一兵一法各有流派 |
| **五层变量联动** | 月令 → 炁候（节气）→ 十神 → 架势 → 装备，全乘法结构使计算顺序无关 |
| **敌人招式牌组** | 每只心猿有独立招式牌组与「势」资源，出招有成本有品阶（常/技/凶/杀） |
| **归墟弃牌** | 手牌溢出进入「归墟」阶段，弃牌按类型化炁（损有余而补不足），拒绝纯损失 |
| **阴阳双阵营** | 阴执（都市戾气：焦躁鬼/加班怨灵/贪嗔蠹）+ 阳华（节令精怪：金吾卫/春雷兽/冰魇） |

## 五、项目结构

```
src/
├── main.tsx                  # 挂载入口
├── App.tsx                   # Screen 状态机（main / loadout / select / battle / result）+ 存档
├── game/
│   ├── engine/               # 确定性战斗引擎（纯函数）
│   │   ├── battle.ts         # 回合状态机 + reducer（含 EFFECT_HANDLERS 穷尽表）
│   │   ├── damage.ts         # 多段伤害结算管线
│   │   ├── hooks.ts          # 二十四节气效果挂载点
│   │   ├── rng.ts            # mulberry32 种子随机
│   │   ├── assertNever.ts    # 穷尽性断言
│   │   ├── battle.test.ts    # 战局行为测试（58）
│   │   ├── contract.test.ts  # 数据-引擎契约测试（33）
│   │   └── diag.test.ts      # 诊断用例（1）
│   ├── data/                 # 纯数据：角色 / 卡牌 / 状态 / 世界设定
│   ├── constants.ts          # 全部数值常量（零引用会被守卫报出）
│   ├── types.ts              # 全部类型（判别联合 + 穷尽映射）
│   └── audio.ts              # 音效播放（仅 UI 可调用，绝不进引擎）
├── components/
│   ├── Screens.tsx           # 主界面 / 编队 / 结算 / 开场（886 行）
│   ├── BattleScreen.tsx      # 战斗屏编排（259 行，只做组装）
│   ├── StanceSelectPanel.tsx # 择道面板（入局三选一）
│   ├── RelicPhase.tsx        # 归墟弃牌阶段
│   ├── battle/               # 战斗屏子组件（20 个：顶栏/架势/我方/敌方/手牌/操作栏/弹反/素材表/布局）
│   ├── fx/                   # Canvas 粒子特效 + 从 CSS 令牌取色
│   ├── svg/                  # 程序化立绘兜底 / 五行纹样 / 状态图标
│   └── ui/                   # 描金面板 / 玉牌按钮 / 流光炁条 / 释义浮层
├── i18n/                     # 国际化骨架（zh-CN 词表 + t() + 存档迁移）
└── styles/
    ├── tokens.css            # 颜色 / 字体 / 间距变量（唯一 hex 出处）
    └── global.css
```

**生成提示词分三册，共用同一套画风与色卡**：

## 九、语言与命名约定

本项目为中文项目，**非必要一律使用中文**：

- 全部说明文档使用简体中文
- 所有**用户可见文本**（角色名、卡牌名与描述、按钮、提示、战报日志）使用简体中文
- 代码注释使用简体中文
- `index.html` 采用 `lang="zh-CN"`

**文件命名强制中文**（硬约束）：

- **素材库**（`public/`）：`语义前缀_中文名`，如 `bg_战场.png`、`char_陆青崖.png`、`enemy_金吾卫.png`
- **文档**（`docs/`）：一律中文名，如 `玩法介绍.md`、`设计哲学.md`、`类图.mermaid`
- 重命名后必须同步更新代码引用（`Figure.tsx` 路径映射、背景 `url()`、`index.html` 图标）与文档交叉链接

**工程必要的英文例外**：代码标识符、`P0/P1/P2`、任务编号、根 `README.md`、
工具链配置文件名、`src/` 下源码文件名（与 import 路径强绑定）。
