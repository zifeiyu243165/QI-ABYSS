## 标记约定（本册新增，请务必先读）

每个条目标题后带一个方括号标记，**决定你要不要改代码**：

| 标记 | 含义 | 你要做什么 |
|---|---|---|
| `【直换】` | 代码里已经有引用点（`url()` 或映射表） | 生成后按同名覆盖 `public/art/` 即可，**零代码改动** |
| `【需接入】` | 界面目前是**纯 CSS / SVG 直接绘制**，还没有引用点 | 生成后需要改组件才能生效（接入点已注明） |
| `【可选】` | 锦上添花，不做也完全能玩 | 自行决定 |

> 判断依据：`【直换】` = 现在缺图会「降级但不报错」；`【需接入】` = 现在这块根本没有图片通道。

## 通用前缀

### A. 界面零件通用前缀（每次生成界面零件都加在最前面）

> **画风**：粗线条二次元国潮插画，赛璐璐平涂，硬边阴影，纯色块，不要渐变过渡、不要写实高光。
> **形式**：**单个界面零部件**，正面平视，**正投影无透视**，居中放置，四周留足纯白空隙。
> **材质铁律**：宣纸米白 / 竹简暖黄 / 绢帛 / 描金铜边 / 青玉 / 金丝楠木，全部平涂。
> **边界**：必须有**清晰、闭合、粗黑的轮廓线**，方便抠图；不要羽化边、不要外发光、不要半透明阴影溢出。
> **可拉伸件**（面板 / 匾额 / 分隔线 / 装备槽）：**中间段做成纯净平铺**，两侧边饰保持固定宽度，这样才能九宫格拉伸不变形。
> **绝对禁止**：任何文字、汉字、字母、数字、签名、水印、mockup 边框、透视网格。

### B. 全屏背景通用前缀（生成 `bg_` 时加在最前面）

> **画风**：粗线条二次元国潮风，赛璐璐平涂，扁平化几何化。
> **形式**：**竖幅全屏背景 390 × 844 比例**，画面铺满不留白边，汉唐建筑与山峦为扁平几何色块。
> **构图铁律**：**中央 55% 区域必须干净留白**（要压立绘、标题与按钮）；所有繁复装饰推到**四条边与四角**。天空有规律排布的几何祥云，云朵形状统一。
> **色彩**：宣纸米白为主底，石青 `#6a9ec4` + 石绿 `#7fa88c` 作山峦，描金 `#d4a843` 点缀云霞。画面明亮，高饱和平涂，**绝不阴森、绝不夜景、绝不用纯黑**。
> **绝对禁止**：任何文字、人物、动物、荧光紫、荧光粉、赛博霓虹蓝、3D 渲染、写实光影、平滑渐变。

### 通用负面提示词（以上两类都必须带上）

> 3D渲染，写实光影，平滑渐变，柔光，环境光遮蔽，古早页游风，塑料质感，厚涂，杂乱无章，元素堆砌，视觉噪音，丑陋，脏污，破损，血腥，恐怖，阴森，鬼气，夜景，纯黑背景，荧光紫，荧光粉，赛博霓虹蓝，英文，数字，文字，水印，签名，透视，等距投影，mockup，网格。

> 回合结束手牌超上限时进入的**全屏覆盖阶段**。当前全部为纯 CSS/SVG 绘制：
> 太极旋涡是 CSS 圆形叠出来的（`RelicPhase.tsx:17`，注释明写「不依赖任何图形资源」），
> 金墨莲花是内联 SVG（8 外瓣 + 8 内瓣，`BattleScreen.tsx:1460` 起）。
> **这一节是「锦上添花」，不做也完全能玩**，但做了会显著提升「大量归墟」的爽感。

### `ui_归墟面板.png` 【可选】【需接入】 — 归墟全屏底（390 × 844 → 生成 1560 × 3376）

> 粗线条二次元国潮插画，赛璐璐平涂。**竖幅全屏底**。整体是**深色但不阴森**的「虚空」：底色为**石青深 `#0b2e59` 与鸦青 `#1a1f2b` 的上下两块硬边平铺**，四周边缘向内散布**规律排布的、向中心旋进的几何云雷纹**（暗示「一切正被吸入归墟」），四角各有一枚较大的描金云头作为视觉锚点。**画面正中必须大面积完全干净**（要压标题「归墟」、手牌列表、太极旋涡与印章），**只有边缘 25% 允许有纹样**。**绝对不要纯黑、不要星空、不要恐怖元素**——要「庄严肃穆的仪式感」，像站在一口深不可测的古井边。有清晰闭合的粗黑轮廓线。无文字。

## 七、生成与接入流程

1. **生图**：按上面的提示词逐张生成。界面零件一律**纯白背景**；`bg_` 全屏底为满幅不透明。
2. **抠图**：所有 `ui_*.png` 跑 `node scripts/抠图.mjs <目录>` 去白底转真 alpha。`bg_*` 不需要。
3. **放置**：全部丢进 `public/art/`，**文件名必须与本文档完全一致**（中文，前缀 `ui_` / `bg_`）。
4. **命名铁律**：一律中文，「语义前缀_中文名」。前缀固定为 `card_`（卡面）/ `ui_`（界面）/ `bg_`（背景）/ `char_`（主角）/ `enemy_`（心猿）。
5. **按标记决定是否改代码**：
   - `【直换】`：**本册没有这一类**（第三册全是尚未接入的新资源）。若日后有素材落到
     已有引用点（如 `bg_` 背景、`card_` 卡面），则直接覆盖同名文件即可。
   - `【需接入】` / `【可选】`：**改代码才能生效**。绝大多数界面零件目前是 CSS/SVG 直接绘制，
     接入时需要改 `src/components/Screens.tsx`（主界面/编队/结算/开场）或
     `src/components/RelicPhase.tsx`（归墟），把对应的 `background` / 边框样式换成
     `backgroundImage: url(...)` 的九宫格（`border-image` 或 `background-size` + `slice`）。
6. **可拉伸件务必九宫格**：`ui_面板底` / `ui_页头匾额` / `ui_复盘卷轴` / `ui_装备槽` /
   `ui_描金分隔线` / `ui_统计行底` 这六类是**变长件**，接入时必须用九宫格拉伸，
   **不要** `background-size: 100% 100%`（会把边饰拉变形）。
7. **缺图必须优雅降级**：接入时保留现有的「图片加载失败就只剩 CSS 底色」模式
   （`Figure.tsx` 的 `onError` → SVG 兜底、`BattleScreen.tsx` 的卡面叠加层就是范例），
   **绝不允许因为少一张图而白屏**。
