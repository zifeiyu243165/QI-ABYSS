## 一、现状盘点（读代码后的结论）

### 1.1 Screen 状态机与现有界面

`src/App.tsx:16` 定义：

```ts
type Screen = 'main' | 'loadout' | 'select' | 'battle' | 'result';
```

| Screen | 组件 | 文件 | 性质 | 出口 |
|---|---|---|---|---|
| `main` | `MainScreen` | `components/Screens.tsx` | 主界面 | → `select`（入局）/ `loadout`（编队） |
| `loadout` | `LoadoutScreen` | `components/Screens.tsx` | 编队 · 命盘 | → `main` |
| `select` | `StanceSelectPanel` | `components/StanceSelectPanel.tsx` | 择道（选人即选架势） | → `battle` / `main` |
| `battle` | `BattleScreen` | `components/BattleScreen.tsx` | 战斗（含归墟 `RelicPhase`） | → `result` / `main`（撤退） |
| `result` | `ResultScreen` | `components/Screens.tsx` | 结算 · 命理复盘 | → `battle`（下一战 / 再来一次）/ `main` |

**覆盖层（非 Screen）**：

| 覆盖层 | 组件 | 触发 | 层级 |
|---|---|---|---|
| 开场仪式 | `IntroSequence` | `startBattle` 后 `showIntro=true`，3.6s 或点击跳过 | `zIndex: 90` |
| 归墟 | `RelicPhase` | 战斗内 `phase === 'relic'` | 战斗屏内 |
| 特效 / 伤害数字 / 反弹字 | `FxLayer` / `DamageNumberLayer` / `ParryGlyph` | 战斗内一次性信号 | 40 / 60 / 80 |

**结论**：新增界面**不需要**新建路由 / 状态库，只需在 `Screen` 联合类型加成员 + 在 `App.tsx` 加渲染分支（`'select'` 就是这么做的）。

## 二、A 主界面（开机画面）美化方案

> 用户原话要点：**当前开机画面观感不足，希望优化视觉、首屏信息层级与入局动线。**
> 现状基线见 §1.2。**不改 `Screen` 数量，只改 `MainScreen` 内部**，风险最低。

### A-1 视觉升级

| # | 项 | 做法 | 为什么 |
|---|---|---|---|
| A1.1 | 标题上匾 | 引入 `ui_标题匾额.png`（320×104）作为「炁渊」二字的**实体承载**，字压在图之上 | 现状只用 textShadow 拟匾额，缺「材质」。匾额是主界面唯一视觉重心 |
| A1.2 | 立绘上座 | 引入 `ui_立绘云座.png`（220×60），置于 `CharacterFigure` 之下、底部对齐 | 立绘现在没有「站的地方」，落不到画面上 |
| A1.3 | 面板化次级信息 | 引入 `ui_面板底.png`，承载「下一战」与进度两块信息 | 三件已生成素材中**这件最通用**，先在主界面落地，成本最低、效果最直接 |
| A1.4 | 分隔与呼吸 | 引入 `ui_描金分隔线.png` 切分「标题区 / 动线区 / 进度区」 | 现状靠 `marginTop` 硬分隔，层级读不出来 |
| A1.5 | 景深分层 | `AmbientBackground` 的双图叠加改为**显式分层**：远山层（`bg_主界面.png`）+ 近景层（`bg_战场.png`），两层各自 `opacity` / `backgroundPosition` / 位移 | 现为同一 `div` 双 `url()` 叠加，层次不可控 |
| A1.6 | 动效克制 | 复用已有类：`cloud-drift`（背景缓移）、`fadeUp`（元素入场）、`gold-breathe`（主 CTA 呼吸）；**不新增 keyframe** | 新增 keyframe 会触发守卫的「死 keyframe」检查，且 `global.css` 不宜频繁动 |

**视觉红线（写进验收）**：

- 严禁荧光紫 / 荧光粉 / 赛博霓虹蓝；严禁纯黑背景；

### A-3 入局动线

**现状动线**（读代码实测）：

```
主界面「入局」→ setScreen('select') → StanceSelectPanel（三选一，选人即选架势）
  → onConfirm(charId) → setSave(selectedCharacterId) → startBattle(pendingCampaign.id, charId)
  → setShowIntro(true) + setScreen('battle') → IntroSequence(3.6s / 点击跳过) → 战斗
```

**问题**：玩家在「入局」前**不知道打哪一局**；且 `pendingCampaign` 取「首个未通关」，**顺序是强制的**，玩家无选择权。

**候选方案**（**需拍板，见 §七 Q1**）：

| 方案 | 动线 | 优点 | 风险 |
|---|---|---|---|
| **甲（推荐）** | 主界面 → **讨伐选择**（B-4）→ 择道（`select`）→ 开场 → 战斗 | 把「已通关进度」变成玩家可见的主线动线；`CAMPAIGNS` 数据已齐，零新数据 | 多一步点击；需新增 `Screen='trial'` |
| 乙 | 主界面 → 择道 → 开场 → 战斗（现状不变），仅主界面 L2 显示下一战 | 零动线改动，改动最小 | 玩家仍无选择权 |
| 丙 | 讨伐页内**同时选人**（合并 `select` 与讨伐） | 回到两步 | 与已交付的 T01 择道面板冲突，需重做 |

**建议默认**：先落 **乙**（L2 预告 + 保持现动线，低风险、可立刻验收），**B-4 讨伐页就绪后再切甲**。
