## 〇、使用规则

### 0.1 三条硬规则

1. **每个条目必须有「外部可观测变化」。** 写不出「玩家能看见/摸到什么不同」的，不许立项——这条直接对应引擎铁律「禁止无响应系统」。
2. **每个条目必须有「验收要点」且可机器验证或可截图验证。** 写「界面更好看」不算验收。
3. **不许在本文定义数值。** 任何新数值先进 `src/game/constants.ts`，本文只引用常量名。

### 0.2 字段定义与优先级

每个条目固定八个字段：**编号**（`B-01` 起顺序编号，只增不改；作废条目保留占位不复用）、**标题**、**模块**、**优先级**、**前置依赖**（必须先完成的条目号或必须先拿到的人类决策 `Q-xx`）、**外部可观测变化**（做完之后玩家/评审/接手者能观测到什么不同）、**验收要点**（可执行、含机器校验命令）、**是否需拍板**。

优先级口径：**P0** = 不做就阻塞交付或构成缺陷；**P1** = 明显收益、无阻塞；**P2** = 可延后、可选、或依赖外部拍板。

**分布：P0 9 条 / P1 13 条 / P2 5 条，合计 27 条。**

### B-13 首屏信息层级 L1–L5（含「下一战」预告）

- **模块**：主界面 · **优先级**：**P0** · **需拍板**：否
- **前置依赖**：B-08（面板底）
- **外部可观测变化**：玩家在点「入局」之前，**能看到下一战叫什么、打谁、在哪**。这是当前首屏最核心的缺口。
- **根因（实测）**：`App.tsx` 早已算出 `pendingCampaign`（首个未通关战役），但**没有传给 `MainScreen`**。
- **五层设计**：

| 层 | 内容 | 权重 | 数据来源 |
|---|---|---|---|
| L1 | 「炁渊」+ 匾额承载 | 最大 | 常量文案 |
| L2 | **下一战预告**：战役名 + 一句描述 + 敌首小像 | 次大（**新增**） | `CAMPAIGNS` + `ENEMY_MAP`，取 `pendingCampaign` |
| L3 | 主 CTA「入 局」 | 强 | — |
| L4 | 次级入口：编队 / 藏经 / 天工… | 中 | 随 B-18~B-23 逐个接入 |
| L5 | 进度 + 落款 | 弱 | `save.clearedCampaigns.length` / `CAMPAIGNS.length` |

- **验收要点**：
  1. 「下一战」显示的战役名 / 描述 / 敌首与 `pendingCampaign` **完全一致**（不是另一套写死数据）；
  2. 390×844 竖屏下五层信息一眼可辨，无遮挡、无横向滚动；
  3. 只新增一个 prop，**不动 `Screen` 状态机**；
  4. 新增文案全走 `t()`，不产生孤儿键。
